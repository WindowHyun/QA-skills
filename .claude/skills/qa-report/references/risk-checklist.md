# 위험 지점 체크리스트 (스택 무관)

코드를 읽으며 이 렌즈를 대입한다. **해당 코드에서 실제로 성립하는 항목만** 리포트에 옮긴다.
각 카테고리는 "무엇을 의심할지"와 "어떤 코드 패턴을 찾을지"로 구성된다.

## 목차

1. 입력과 경계값
2. 분기와 조건 누락
3. 상태와 생명주기
4. 에러 처리와 실패 복구
5. 외부 연동 (네트워크·서드파티)
6. 데이터 정합성과 영속성
7. 동시성·순서·타이밍
8. 권한과 보안
9. 하위 호환성과 마이그레이션
10. 성능과 규모
11. 환경·설정 차이
12. 관측 가능성 (로그·모니터링)

---

## 1. 입력과 경계값

**의심할 것**: 값이 있다고 가정하는 곳, 범위 검사가 없는 곳.

- null / undefined / 빈 문자열 / 빈 배열 / 0 / 음수
- 최소·최대 경계와 그 ±1 (길이 제한, 페이지 크기, 수량, 금액)
- 타입 강제 변환 (문자열 "0"이 falsy가 아닌 언어, 숫자 파싱 실패)
- 유니코드·이모지·공백·개행, 매우 긴 문자열
- 소수점 정밀도, 반올림 방향, 통화 단위 (금액 계산이면 항상 P0 후보)
- 날짜: 타임존, 월말/윤년, 서머타임, 과거·미래 날짜

**찾을 패턴**: `parseInt`, `Number(`, `.length`, `substring`, `slice`, `toFixed`, 나눗셈 `/`, `%`,
검증 없이 바로 쓰는 요청 파라미터, `!value` 로 0/빈값을 함께 걸러내는 코드.

## 2. 분기와 조건 누락

**의심할 것**: 새로 생긴 조건이 기존 경로를 바꾸는지.

- if/else if 사슬에서 빠진 케이스, else 없는 분기
- switch의 default 누락, enum/상태값이 추가될 때의 처리
- 조건 우선순위 변경 (AND/OR 결합, 부정 조건)
- early return이 뒤따르는 정리(cleanup) 코드를 건너뛰는지
- 기능 플래그(feature flag) on/off 양쪽 경로

**찾을 패턴**: 디프에서 조건식 자체가 바뀐 줄, 새로 추가된 `return`, `switch`, 삼항 연산자 중첩.

## 3. 상태와 생명주기

**의심할 것**: 두 번 호출하거나, 중간에 끊거나, 순서를 바꿨을 때.

- 중복 호출 / 중복 제출 (버튼 연타, 재시도, 멱등성)
- 초기화 전 접근, 정리(해제) 후 접근
- 캐시 무효화 시점, 오래된(stale) 캐시로 인한 불일치
- 화면 이탈/재진입, 백그라운드 전환, 세션 만료 후 복귀
- 전역·싱글턴 상태가 요청 간에 새는지

**찾을 패턴**: `cache`, `static`, 모듈 최상위 가변 변수, `useEffect`/`onDestroy`/`dispose` 류의 생명주기 훅,
구독(subscribe) 후 해제되지 않는 리스너.

## 4. 에러 처리와 실패 복구

**의심할 것**: 실패했을 때 사용자와 데이터가 어떤 상태로 남는지.

- 삼켜지는 예외 (빈 catch, 로그만 하고 계속 진행)
- 실패 시 부분 완료 상태로 남는 흐름 (A는 저장, B는 실패)
- 사용자에게 노출되는 에러 메시지의 정확성, 내부 정보 노출
- 재시도 로직의 종료 조건, 재시도가 부작용을 반복시키는지
- 실패 후 다시 시도할 수 있는지 (복구 경로 존재 여부)

**찾을 패턴**: `try`/`catch`, `.catch(`, `except`, `recover`, `throw`를 삼키는 지점, `finally` 누락.

## 5. 외부 연동 (네트워크·서드파티)

**의심할 것**: 상대가 느리거나 죽거나 이상한 값을 줄 때.

- 타임아웃 설정 유무와 값
- 4xx / 5xx / 빈 응답 / 스키마가 다른 응답
- 응답 필드 누락 시 기본값 처리
- 오프라인·약한 네트워크, 중간 끊김
- 레이트 리밋, 쿼터 초과

**찾을 패턴**: `fetch`, `axios`, `http`, `request`, SDK 클라이언트 호출, `await` 뒤 에러 처리 부재.

## 6. 데이터 정합성과 영속성

**의심할 것**: 저장된 것과 보여지는 것이 어긋나는 경우.

- 트랜잭션 경계, 롤백되지 않는 부수 효과 (파일 쓰기, 외부 호출, 이벤트 발행)
- 고유 제약·외래키 위반, 중복 레코드 생성
- 삭제 시 연관 데이터 처리 (soft delete 포함)
- 저장 형식 변경 시 기존 데이터 읽기
- 목록/집계 값과 상세 값의 불일치

**찾을 패턴**: `INSERT`/`UPDATE`/`DELETE`, ORM save/create, `transaction`, `commit`, 여러 저장소를 연속으로 쓰는 코드.

## 7. 동시성·순서·타이밍

**의심할 것**: 두 개가 동시에 일어나거나, 늦게 도착할 때.

- 경쟁 상태 (같은 리소스 동시 수정, 재고·잔액 차감)
- 비동기 응답 도착 순서 역전 (늦게 온 예전 요청이 최신 결과를 덮어씀)
- 락·큐의 데드락, 처리 누락
- 폴링/디바운스/스로틀 간격과 중복 실행
- 스케줄러·배치의 중복 실행, 실행 시간 겹침

**찾을 패턴**: `Promise.all`, `async` 루프, `setTimeout`, `lock`, `mutex`, `queue`, 증감 연산 `+= `.

## 8. 권한과 보안

**의심할 것**: 다른 사람의 것을 볼 수 있거나 바꿀 수 있는지.

- 인증 여부 확인 누락, 만료 토큰 처리
- 리소스 소유권 확인 없이 ID만으로 접근 (IDOR)
- 역할·권한별 분기 (관리자/일반/게스트)
- 입력이 쿼리·명령·템플릿에 직접 삽입되는지
- 민감정보의 로그·응답·URL 노출

**찾을 패턴**: 라우트 핸들러 진입부의 권한 검사, `userId` 를 요청 body에서 받는 코드, 문자열로 조립한 쿼리,
`console.log`/로거에 실린 객체 전체.

## 9. 하위 호환성과 마이그레이션

**의심할 것**: 기존 사용자·기존 데이터·기존 클라이언트.

- API 응답 필드 제거·의미 변경, 필수 파라미터 추가
- 저장 스키마 변경 시 기존 레코드 (마이그레이션 유무, 롤백 가능 여부)
- 구버전 클라이언트/캐시된 프런트엔드가 신규 서버와 통신
- 설정 키 이름 변경, 기본값 변경
- 업그레이드 도중 상태 (구·신 버전 동시 구동)

**찾을 패턴**: 디프에서 **삭제되거나 이름이 바뀐** 필드·파라미터·설정 키, 마이그레이션 파일, 버전 상수.

## 10. 성능과 규모

**의심할 것**: 데이터가 100배일 때.

- 반복문 안의 질의·네트워크 호출 (N+1)
- 페이징 없는 전체 조회, 메모리 적재
- 인덱스 없는 조건 검색, 정렬
- 대용량 파일·이미지 처리, 업로드 크기 제한
- 첫 화면 지연, 불필요한 재렌더링·재계산

**찾을 패턴**: 루프 내부의 `await`/쿼리, `findAll`, `SELECT *`, 정렬·필터 체인, 캐시 없는 고빈도 경로.

## 11. 환경·설정 차이

**의심할 것**: 내 로컬에서만 되는 것.

- 환경변수 누락 시 동작 (기본값? 크래시? 조용한 오작동?)
- 개발/스테이징/운영 간 설정 분기
- 타임존·로케일·언어 설정
- 브라우저·OS·디바이스·해상도 차이 (해당 시)
- 빌드 모드(dev/prod) 별 차이

**찾을 패턴**: `process.env`, `os.environ`, `getenv`, 설정 파일 로딩, `NODE_ENV === ` 같은 분기.

## 12. 관측 가능성

**의심할 것**: 문제가 나도 아무도 모르는 상황.

- 실패 경로에 로그·메트릭이 없어 QA가 재현 결과를 확인할 수 없는 경우
- 로그 레벨이 부적절해 운영에서 원인 추적이 불가능한 경우

이 카테고리는 테스트 케이스보다는 리포트의 "개선 제안"으로 적는 편이 자연스럽다.
